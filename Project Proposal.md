**Project Proposal: RNA Aptamer Candidate Ranking Tool**

**Target:** ICDM 2026 Demo Track (4-page IEEE paper, submission deadline 20 August 2026\) **Status:** Draft for team discussion – first meeting 20 July 2026

---

**1\. What we're building**

A tool for ranking candidate RNA aptamer sequences against a chosen target, designed to work with sequences generated by RNA foundation models (RNA FMs) rather than only sequences discovered via SELEX. The biologist supplies candidate sequences and a target, and receives an interpretable, ranked shortlist with the evidence behind each ranking.

**2\. Why this matters**

RNA FMs now let us design large numbers of candidate RNA sequences for synthetic biology, therapeutic, and diagnostic applications. But every candidate still needs lab validation before it can be used, and that validation is expensive and slow, creating a bottleneck for sequence design. Computational prioritisation reduces the number of candidates that need wet-lab testing, saving time and money and improving the odds of identifying a functional sequence.

RNA aptamers are a natural test case as they are a common benchmark sequence type for newly developed RNA FMs and are independently valuable as diagnostic and therapeutic molecules. Current computational methods for prioritising them are underdeveloped and were largely built for SELEX-derived candidates, not FM-generated ones; this is the gap our tool addresses.

**3\. Literature gap**

Existing computational approaches to aptamer evaluation fall into four broad categories: sequence-based clustering/counting by SELEX read enrichment, structural-motif tools layering ViennaRNA-based secondary structure onto sequence clustering, ML/deep-learning binding predictors using sequence representations (e.g. RaptScore) and structure-based docking/MD, which is the most detailed but most expensive, and so is reserved for small final shortlists.

**The gap:** none of these provide a systematic, modular, multi-stage pipeline designed specifically for FM-generated candidates (as opposed to SELEX-enriched pools), that is target-swappable, and that is explicit about the limits of target-aware scoring rather than presenting binding predictions as ground truth.

**4\. Biology background** 

* **RNA** is a single-stranded biological molecule made of 4 nucleotides (A, C, U, G). It folds into 2D/3D shapes and plays diverse roles in cells and has many applications in bioengineering/medicine.  
* **RNA aptamers** are short RNA sequences (roughly 20–100 nucleotides) that fold into shapes able to bind a target molecule (such as a protein or small molecule), and can be used to detect or inhibit that target, making them useful as diagnostic tools or therapeutics.  
* **This is a low-data problem.** There's very little labelled binding data for aptamer–target pairs, and computational binding predictors (including docking) are known to be error-prone and shouldn't be treated as proof of binding. This directly shapes the tool's design: we prioritise features that give biologists genuine signal, and we're explicit about what each score can and can't tell you.

**5\. Inputs and outputs**

**Input:**

* A .txt or .csv file of candidate RNA sequences (one per row, ACUG alphabet, \~20–100 nt)  
* A target, specified as a PDB ID (protein-binding aptamers only for this demo – small-molecule-binding aptamers are out of scope)

**Batch size – proposal for discussion:** Tier 1 scoring (ViennaRNA \+ forgi) is cheap per sequence, so it should comfortably handle batches in the thousands. Tier 2 (target-aware, per Section 6\) is more expensive per sequence since it involves the target structure, so I'd propose running Tier 1 on the full batch and only carrying the top N (e.g. top 200–500, mirroring the Stage 3→4 handoff in Laura's thesis pipeline) through Tier 2\. **This needs engineering input** — what batch size and per-candidate compute time is actually comfortable for a 3-week build and for a live demo?

**Output:** a dashboard showing:

* A ranked list with per-candidate score breakdowns across both tiers  
* Structure diagrams (not just dot-bracket strings) for the top \~50 candidates  
* An inline shuffled-control comparison (see Tier 1 below)  
* A natural-language explanation panel per candidate (optional pending time constraints)

**6\. What happens inside the tool: two scoring tiers**

**Tier 1 — Intrinsic quality (target-agnostic)**

Doesn't change when the target changes. Scored against reference distributions from Laura's curated validated-aptamer corpus (\<5000 sequences) rather than fixed/arbitrary thresholds.

| Component | Method / tool | Output |
| ----- | ----- | ----- |
| Sequence validity & composition | Basic checks \+ corpus GC/length distribution comparison | Pass/fail \+ reference-distribution score |
| Secondary structure stability | ViennaRNA (RNA.fold\_compound) | MFE, ensemble defect, positional entropy |
| Structural element features | forgi (parses ViennaRNA dot-bracket output) | Loop count/size, stem fraction, hairpin presence — the biologist-facing features our expert conversations flagged as most useful |
| Composite Tier 1 score | Rank aggregation across the above | Single interpretable score \+ breakdown |
| Shuffled-control check | Dinucleotide-preserving shuffle (ViennaRNA/ushuffle), same scoring applied | Shows whether a candidate scores meaningfully better than a composition-matched shuffled negative, surfaced directly in the dashboard, not just used internally |

**Tier 2 — Target-aware plausibility (target-swappable, non-docking)**

Swapping the target only touches this tier – everything in Tier 1 is unaffected. No docking or MD; instead cheap, physically-motivated compatibility checks.

| Component | Method / tool | Output |
| ----- | ----- | ----- |
| Cavity/pocket detection on target | fpocket on the input PDB structure | Candidate binding pocket location \+ dimensions |
| Geometric compatibility | Compare aptamer's predicted loop/accessible-region sizes (from Tier 1's forgi output) against pocket dimensions | Compatibility score, framed as plausibility not prediction |
| Electrostatic compatibility (stretch goal) | APBS / PDB2PQR — check whether target surface has positive character compatible with RNA's negative charge | Secondary plausibility signal, if time allows |
| Composite Tier 2 score | Combine available signals | Target-specific plausibility score, clearly labelled as such in the UI |

**Explicitly out of scope for this tool:** docking, molecular dynamics, sensitivity-analysis-across-weighting-schemes and any learned binding-affinity predictor unless time allows late in the build (RaptScore-style approaches are worth a feasibility look, but shouldn't be assumed into the 3-week scope).

**7\. Explanation panel**

A lightweight LLM call over each candidate's existing score breakdown, generating a plain-language explanation (e.g. *"scores well on ensemble defect and loop accessibility, moderate diversity, shares a motif with a known NDM-1 reference aptamer"*). This feature will make the live demo more compelling – comparable to the "reasoning panel" in PersoPilot, one of the reference papers we reviewed. **Engineering input – feasibility in the timeframe?**

**8\. Demo plan**

* **Primary target:** NDM-1, using Laura's existing corpus, generation pipeline, and PDB structure prep (PDB 3SPU, per her thesis work).  
* **Secondary target (for the paper's generalisability claim):** KPC-2, to show the tool isn't NDM-1-specific without needing a second full validation study.  
* **Generation source:** fine-tuned RNAGenesis output.   
* **Backup plan:** if fine-tuning on Laura's general aptamer corpus isn't complete in time, fall back to the IGFBP3 dataset (AptaDiff Dataset A), which RNAGenesis is already fine-tuned on. **Dependency risk** **– flag at meeting**.

**9\. Evaluation — proposed comparison groups and tables**

**Three comparison groups**, scored through the full tool:

1. **Random RNA** — generated at matched length distribution and matched nucleotide frequencies (negative control)  
2. **FM-generated candidates** — fine-tuned RNAGenesis output for the chosen target  
3. **Real validated aptamers** — from Laura's curated corpus, used as a positive control (candidates already known to fold/bind for *some* target, even if not the specific target in Tier 2\)

**Possible tables/figures for the paper:**

* **Table/figure 1:** Tier 1 composite score distributions across the three groups (violin or box plot) — shows the tool discriminates real aptamer-like sequences from random sequences, the single cleanest quantitative claim we can make cheaply.  
* **Table/figure 2:** Shuffled-control comparison for the FM-generated group specifically — shows structural scoring is doing real work, not just responding to nucleotide composition.  
* **Table/figure 3:** Tier 2 target-plausibility comparison, NDM-1 vs KPC-2 — do the same top-ranked candidates score differently when the target is swapped? This is the evidence behind the "target-swappable" claim.  
* **Figure 4 (demo screenshot):** the dashboard itself, showing a ranked shortlist with score breakdown and explanation panel for a handful of top candidates — this is the figure a demo-track reviewer actually wants to see.

**Open question for the team:** do we also want a single headline number (e.g., "the top-20 tool-ranked candidates include X% of held-out real aptamers" or similar) — this would need a way to hold out some real aptamers rather than using them all as reference distribution. Worth discussing whether this is feasible given corpus size (\<5000).
